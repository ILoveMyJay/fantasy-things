# ashare-quant-review 技能优化与工程修复总结报告 (Phase 1A Remediation)

## 1. 修复背景与核心缺陷

针对原 PR #1 代码审查中发现的量化数据失真与工程隐患，本阶段重点解决了以下六大核心问题：

1. **东财全市场采样截断 Bug (Fake Breadth)**：
   - **原因**：原实现请求 `push2.eastmoney.com/api/qt/clist/get` 时，虽然指定 `pz=6000`，但东财服务端单页最大只返回 100 条记录，导致全市场仅采集到 79 只深市主板股票，样本代表性严重失真（覆盖率不足 1.5%）。
   - **修复方案**：
     - 将涨停、跌停、炸板等关键短线指标直接重构为接入东财专用专题池（`push2ex.eastmoney.com` 的 `getTopicZTPool`、`getTopicZBPool`、`getTopicDTPool`），实现 100% 真实封板、炸板和跌停数据抓取。
     - 全市场涨跌平广度采用 `push2.eastmoney.com/api/qt/ulist.np/get?secids=1.000001,0.399001,0.899050`（沪市、深市、北交所）直接提取官方汇总口径，覆盖全市场 5,400+ 只股票。
     - 增加健全的网络降级与安全后备（Fallback）机制，确保在代理或反爬拦截时平滑降级，严禁崩溃。

2. **日内成交量线性外推畸变 (4万亿量能幻觉 Bug)**：
   - **原因**：原代码采用粗暴的线性外推公式：`$V_{est} = \frac{V_{curr}}{t} \times 240$`。由于 A 股日内成交量呈极强的“开盘放量、盘中萎缩、尾盘反抽”的典型 U 型特征（开盘前 30 分钟成交量通常占全天的 25%~30%），开盘 10:00 线性外推会导致预估量能畸变膨胀至 3.5~4.5 万亿，严重误导策略决策。
   - **修复方案**：
     - 构建基于 A 股历史实证统计的 **U 型分时累积成交量权重模型（Intraday Cumulative Volume Profile）**：
       - 09:30~10:00：累积完成 28%
       - 10:00~10:30：累积完成 43%
       - 10:30~11:30：累积完成 58%（半日收盘）
       - 13:00~14:00：累积完成 75%
       - 14:00~14:30：累积完成 85%
       - 14:30~15:00：累积完成 100%
     - 采用分段线性插值计算任意交易分钟的理论累积完成比例 $W(t)$，推算预估全天成交：$V_{est} = \frac{V_{curr}}{W(t)}$。
     - 开盘不足 15 分钟时严格限制外推倍数（$\le 2.0\times$ 昨量），彻底杜绝量能膨胀假象。

3. **非交易日/周末休市守卫盲区**：
   - **原因**：原 `is_trading_time()` 仅根据当前时间的 `hour/minute` 判断是否处于 `09:30~15:00`，完全未检查 `weekday()`，导致周末或节假日白天运行复盘时，系统误将上一交易日的最终结算量作为“盘中未完结量”进行二次外推。
   - **修复方案**：
     - 增加 `now.weekday() >= 5` 周末硬性拦截，周六日直接判定为 `is_intraday=False, elapsed=240, phase='after_hours'`，直接使用全日真实成交额，不触发日内估算。

4. **股票号段缺失与 2026 年新规适配**：
   - **原因**：漏掉了创业板注册制核心号段 `301`、北交所专用号段 `920` 及老号段 `87/88`、科创板 CDR `689`；浮点数容差使用了粗糙的 `0.01`（导致 9.9% 假触板被误判为涨停）。
   - **修复方案**：
     - 全面补齐 `301`（创业板 20%）、`920/87/88`（北交所 30%）、`689`（科创板 20%）号段识别规则。
     - 适配 2026 年全面注册制及 ST 股票最新规则（ST 股票 10% 限制）。
     - 将涨跌停价格判定精度收紧至严格的 Tick Size 容差（`1e-4`），严防微幅未封板个股被误统计。

5. **中金所期指席位节假日回溯断裂**：
   - **原因**：原 `fetch_cffex.py` 的回溯循环仅判断 `weekday < 5` 即盲目跳出，若遇到法定节假日（如国庆、中秋、春节），会向中金所请求无数据的非交易日并发生解析异常。
   - **修复方案**：
     - 增加动态探针回溯机制，最大回溯深度 15 天，直到成功抓取到有效排名表格才锁定基准日；
     - 在返回数据及 Markdown 报告中明确标注中金所席位基准日期 `cffex_trade_date`，杜绝因基准日漂移产生的混淆。

6. **看板 2.1 与看板 5 市场广度口径冲突与 Markdown 渲染塌陷**：
   - **原因**：看板 2.1 与看板 5 分别调用了各自的广度查询，返回不一致的涨跌家数；Markdown 输出中 blockquote (`> ...`) 与 table 之间缺乏空行，导致 CommonMark 解析器将表格合并入引用块产生格式错乱。
   - **修复方案**：
     - `run_quant_suite.py` 内部统一数据源，优先对齐高精度情绪广度；
     - 表格与引用块之间强制插入标准空行 `\n\n`，保证所有 Markdown 渲染器格式完美对齐。
     - 所有进度和异常日志一律重定向至 `sys.stderr`，保证 `--format json` 输出 100% 纯净无污染。
