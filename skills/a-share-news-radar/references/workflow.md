# 共用流程与规则

两个阶段都要走这份流程。Phase 1 / Phase 2 各自的特有步骤见
`workflow-phase1.md` / `workflow-phase2.md`。

## 13 步共用流程

1. 默认取最近 24 小时新闻。盘后任务用全天收盘数据；盘中任务覆盖盘前与盘中
2. 优先一手/高可信来源：官方发布、交易所披露、公司公告、政府通知、主流财经媒体、商品与行业数据商
3. **按底层事件去重**，不按标题去重。同一催化剂的多篇报道合并成一个事件
4. 提取事件事实：时间、主体、地点、量级、受影响产品或行业、政策状态、已确认还是推测
5. 读 `source-policy.md`，确定来源质量，再决定某只股票是「直接证据」还是「仅是线索」
6. 读 `event-taxonomy.md`，用于事件分类与传导路径推理
7. 读 `a-share-mapping.md`，把主题映射到候选池。**种子列表只是备忘，不是事实来源**
8. 读 `candidate-verification.md`，并主动从当前新闻、公告、行业文章中**动态发现**更新、更相关的候选
9. 核查每只候选：上市状态、业务相关性、证据标签、来源质量。已退市 / 停牌 / 关联弱的剔除
10. 有结构化事件数据时用 `score_events.py` 做确定性排序；否则手动套用同一套评分维度
11. 读 `report-template.md`，保证输出形状一致
12. **热搜与热度事件扫描**（两阶段均需执行）
    - 搜索当日/次日文娱热度：「今日热搜 综艺」「今日热播剧 排行」「热搜 爆款 IP」
    - 识别**平台归属**（芒果TV / 爱奇艺 / 腾讯视频）→ **A 股关联**（优先平台运营方，其次内容制作方，最后周边概念）
    - **仅在「进入热搜前列且 A 股有直接关联公司」时纳入**，避免噪音
    - 数据源优先级：微博热搜 > 豆瓣热播剧榜 > 抖音热榜 > 知乎热榜；微博不可直连时用聚合站（tophub.today）
13. **多空方向列（必须）**——每只候选股除证据标签外，必须标注 `✅正面` / `⚠️负面` / `👀中性观察`：
    - `负面暴露` → 固定 `⚠️负面`
    - `情绪映射` → 默认 `👀中性观察`（除非有明确多空证据）
    - `公告确认` / `业务归属` / `产业链推断` → 跟随事件方向
    - **双向事件**（如中美谈判：成则出口恢复、破则管制加码）必须带条件，写 `✅正面（若休战延期）` / `⚠️负面（若管制加码）`，不得只写单边
    - 用表格呈现时方向列放最前，前缀 emoji 便于扫读

## Reasoning Rules

- 优先一阶受益方，而非远距离概念名。一阶指收入、成本、产能、订单、政策资质或商品价格能合理变化
- 区分确认事实与解读。链条不直接时用「确认事实」「推断」「待验证」措辞
- 包含负面与二阶效应。战争可能利好石油、黄金、航运、国防，同时伤害航空、以油为原料的化工、风险偏好
- 惩罚拥挤主题。某板块或个股已连续多日大涨、或媒体一致看多时，标注「拥挤/追高风险」
- 惩罚弱关联。故事主要讲港股或海外公司、A 股只是共享标签时，标「情绪映射」
- 动态核查优先于种子列表。新证据显示业务已变、有新上市公司更相关、或老候选已弱化时，以新证据为准
- **验证股价走势后再标方向**：标「直接受益」或「负面暴露」前，必须用 `market_snapshot.py kline` 或 `metrics` 核实该股当日或近期实际走势。逻辑上应受损但股价上涨时，降级为「观察/核实」并注明背离原因
- **区分短期价格波动与基本面变化**：商品短期涨跌不等于相关股票同向运动，需考虑是否已 price in、预期差、对冲因素、期货现货领先滞后
- 尽量给每只股票标来源质量 `S` / `A` / `B` / `C`。C 级来源与概念页只能提供线索，不能单独支撑「直接受益」或 `High`
- 只有具备 `公告确认` 或明确 `业务归属` 才可放入「直接受益」；媒体only、市场概念、远距离供应链放「观察/核实」
- 绝不给买卖持有指令、目标价、收益承诺或个性化配置建议

## Data Quality Rules

- **行情数据必须有源**：所有指数点位、涨跌幅必须来自 `market_snapshot.py` 实际输出，禁止编造、推算或凭记忆填写
- **交叉验证**：多源数据不一致时以权威源为准，并注明来源
- **时效标注**：盘中数据标注截止时间，收盘数据标注「收盘」
- **宁缺毋滥**：无法确认时明确写「行情数据暂未获取」，不用模糊描述替代具体数字
- **新闻与行情分离**：Market Pulse 中行情数据与新闻事件分析分开呈现
- **事件日期必须验证**：即将发生的事件必须搜索确认确切日期，不能凭记忆推测
- **预期和实际严格分离**：盘前预期内容与盘后确认内容用不同标签，不得混用

