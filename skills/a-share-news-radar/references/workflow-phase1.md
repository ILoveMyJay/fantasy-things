# Phase 1：盘前预期扫描

运行窗口 **08:00–09:00**，或前一日 **20:00–22:00**。

**本阶段不取行情数据**——尚未开盘，或刚开盘数据无意义。若需要判断今天是否交易日，
用 `market_snapshot.py tradecal`（只读 K线日期，不消耗行情额度）。

## 步骤

1. **扫描未来日历事件**——按 `calendar-scanning.md` 的 10 个维度搜索未来 1–3 个交易日的确定性事件。
   每个事件必须标注「已确认日期：来源链接」或「待确认：仅有传闻」，不能凭记忆推测日期
2. **事件影响链分析**——事件类型（参照 `event-taxonomy.md`）→ 预期传导路径 → 受益/受损主题。
   必须区分**第一波（预期行情）**与**第二波（落地行情）**
3. **主题方向为主，不点名个股**——Phase 1 的产物是方向，不是股票池。
   若确有股票级映射需求，必须标 `[预期/待确认]`，否则 `lint_report.py` 会判为不合格
4. **标注行情状态**——写「数据待开盘后确认」

## 输出要求（Template A）

给 3–7 个最高优先级的**即将发生事件**及**预期分析**，每个事件包含：

- 事件摘要 + 已确认日期 + 来源链接
- 事前影响评估：可能发生什么、哪些板块/主题受影响
- **预期路径区分**：第一波（预期行情）/ 第二波（落地行情）
- A 股主题方向：以行业/主题名为主，不点名个股；若有股票级映射，标 `[预期/待确认]`
- 事件确定性：High（已确认日期）/ Medium（广泛报道未确认）/ Low（传闻）
- 触发日期与时间
- 失效条件：什么情况下事件取消或影响改变
- 行动建议：标注哪些是「提前布局」「事件当日观察」「事件落地后确认」

## 常见错误

| 错误 | 后果 |
|---|---|
| 在 Phase 1 里取实时行情 | 数据无意义，且浪费请求 |
| 直接点名具体股票 | 盘前给个股名单等于给交易建议，lint 会拦 |
| 事件日期不验证就写 | 传闻当事实，最容易被事后打脸 |
| 只写「受益方向」不写失效条件 | 无法复盘，判断不可证伪 |

## 自检

```bash
/usr/bin/python3.11 scripts/lint_report.py report.md --phase phase1
```
